# 定位策略规格

本文档定义程序启动台中全部参数定位策略的字段、解析规则、写回行为和限制。实现以 `src/lib/locators/strategies/` 为准；定位器类型和策略接口位于 `src/lib/locators/model.ts`，模式注册表位于 `src/lib/locators/registry.ts`。

## 1. 通用约定

- 行号从 `1` 开始。
- 列号从 `0` 开始。
- 区间结束列是排他位置，即 `[startColumnIndex, endColumnIndex)`。
- 文本写回只替换定位器解析出的字符区间，不执行语言级语法分析或自动补全变量声明。
- 多个输入参数会先全部解析和校验，再从文本末尾向前替换，避免前一个替换影响后一个的字符偏移。
- 任意输入范围解析失败、多个输入范围重叠或参数值校验失败时，本次输入写回整体取消。
- 编辑器发生跨行插入或删除时，基于坐标的策略会更新行号；语义定位策略不修改规则字段，而是在新文本上重新解析。
- 当前重定位不处理同一行内目标前方字符变化造成的列偏移。完整规则见 [行定位自动重定位方案](./line-relocation-plan.md)。

## 2. 界面模式与持久化类型

| 界面模式 | `locator.kind` | 说明 |
|---|---|---|
| 自动 | `autoPosition` | 由编辑器选区创建，可用 Token 相对边界增强同一行内的稳定性 |
| 固定长度 | `rowColumn` | 用起止行列定义精确范围 |
| 分段 | `delimited` | 用分隔符和分段序号定位 |
| 起始列 | `startColumn` | 从指定行列定位到行尾 |
| 整行 | `wholeLine` | 定位一整行 |
| 多行 | `multiLine` | 定位起止行覆盖的完整范围 |
| 不定行 | `marker` | 定位两个文本标记之间的内容 |
| JSON 路径 | `jsonPath` | 按 JSON 对象键和数组索引定位 |
| XML 路径 | `xmlPath` | 按 XML 元素、属性或文本定位 |
| 模式匹配 | `pattern` | 按正则表达式、捕获组和出现序号定位 |

界面模式名不属于工程文件格式。写入 `parameters.json` 的是上表右侧的 `kind` 和对应字段。

## 3. 自动定位 `autoPosition`

适用场景：用户直接在编辑器中选择一段文本，希望先按当前行列保存，同时尽量容忍同一行内值长度变化。

字段：

| 字段 | 类型 | 含义 |
|---|---|---|
| `startRowIndex` | 整数 | 选区起始行，从 1 开始 |
| `startColumnIndex` | 整数 | 选区起始列，从 0 开始 |
| `endRowIndex` | 整数 | 选区结束行，从 1 开始 |
| `endColumnIndex` | 整数 | 选区结束列，排他 |
| `tokenRange` | 可选对象 | 单行选区额外保存的 Token 相对边界 |

创建规则：

- 创建参数时根据当前编辑器选区计算起止行列。
- 单行选区会尝试生成 `tokenRange`；跨行选区只保留行列坐标。
- Token 化以空白、标点和符号为边界，连续普通字符组成一个 Token。
- `tokenRange` 记录 Token 总数、起止 Token 序号，以及起止位置相对 Token 边界的偏移。

解析规则：

- 没有 `tokenRange` 时，按起止行列解析，行为与固定长度相同。
- 有 `tokenRange` 时要求目标仍在同一行内。
- 当前行 Token 数量与保存值不一致时，定位判定失效。
- Token 数量一致时，根据 Token 的新列位置和保存的相对偏移重新计算实际行列。

示例：

```json
{
  "kind": "autoPosition",
  "startRowIndex": 2,
  "startColumnIndex": 8,
  "endRowIndex": 2,
  "endColumnIndex": 12,
  "tokenRange": {
    "tokenCount": 7,
    "startTokenIndex": 4,
    "startOffsetFromTokenStart": 0,
    "endTokenIndex": 6,
    "endOffsetFromTokenEnd": 0
  }
}
```

写入与重定位：

- 输入值按原文直接替换范围，不增加引号或语言字符串字面量。
- 写入后更新结束行和结束列。
- 如果写入导致 Token 边界不再与固定坐标一致，会移除 `tokenRange`，保留固定行列。
- 编辑器跨行编辑时映射起始行和结束行，保留 `tokenRange`。

## 4. 固定长度 `rowColumn`

适用场景：目标位置稳定，适合固定格式数值、单位或输出行。

字段：

| 字段 | 类型 | 含义 |
|---|---|---|
| `startRowIndex` | 整数 | 起始行，从 1 开始 |
| `startColumnIndex` | 整数 | 起始列，从 0 开始 |
| `endRowIndex` | 整数 | 结束行，从 1 开始 |
| `endColumnIndex` | 整数 | 结束列，排他 |

解析规则：

- 起始行和结束行必须存在。
- 起始行不能小于 1，结束行不能早于起始行，起始列不能小于 0。
- 同行定位时，结束列不能早于起始列。
- 起止列超过对应行长度时按行尾截断。

示例：

```json
{
  "kind": "rowColumn",
  "startRowIndex": 4,
  "startColumnIndex": 12,
  "endRowIndex": 4,
  "endColumnIndex": 24
}
```

写入与重定位：

- 输入值按原文直接替换范围。
- 写入多行内容后，结束行和结束列会随替换文本更新。
- 编辑器跨行编辑时映射起始行和结束行。

## 5. 分段 `delimited`

适用场景：单行内容使用固定分隔符组织，例如逗号、制表符或分号分隔的数据。

字段：

| 字段 | 类型 | 含义 |
|---|---|---|
| `rowIndex` | 整数 | 目标行，从 1 开始 |
| `separator` | 字符串 | 非空分隔符 |
| `fieldIndex` | 整数 | 分段序号，从 0 开始 |

解析规则：

- 使用完整分隔符拆分目标行。
- 分段序号必须是非负整数。
- 序号超出实际分段数量时定位失败。
- 选中分段的首尾空白会在返回值和字符范围中被裁掉。

示例：

```json
{
  "kind": "delimited",
  "rowIndex": 3,
  "separator": ",",
  "fieldIndex": 2
}
```

写入与重定位：

- 输入值直接替换选中分段的有效文本范围。
- 不自动补充或删除分隔符。
- 编辑器跨行编辑时映射 `rowIndex`。

## 6. 起始列 `startColumn`

适用场景：目标从某一行指定列开始，并持续到该行末尾。

字段：

| 字段 | 类型 | 含义 |
|---|---|---|
| `rowIndex` | 整数 | 目标行，从 1 开始 |
| `startColumnIndex` | 整数 | 起始列，从 0 开始 |

示例：

```json
{
  "kind": "startColumn",
  "rowIndex": 6,
  "startColumnIndex": 8
}
```

解析规则：

- 目标行必须存在。
- 起始列超过行长度时按行尾截断。
- 返回从起始列到行尾的内容，并裁掉首尾空白。

写入与重定位：

- 输入值直接替换有效文本范围。
- 编辑器跨行编辑时映射 `rowIndex`。

## 7. 整行 `wholeLine`

适用场景：整行内容就是一个参数，且不需要排除行尾换行符之外的任何内容。

字段：

| 字段 | 类型 | 含义 |
|---|---|---|
| `rowIndex` | 整数 | 目标行，从 1 开始 |

示例：

```json
{
  "kind": "wholeLine",
  "rowIndex": 8
}
```

解析规则：

- 目标行必须存在。
- 范围从行首到行尾，不包含行尾换行符。
- 不裁剪行内空白。

写入与重定位：

- 输入值直接替换整行有效范围。
- 若输入值包含换行，会写入多行文本；定位器本身不改变，再次解析时仍按单行规则处理。
- 编辑器跨行编辑时映射 `rowIndex`。

## 8. 多行 `multiLine`

适用场景：一个参数覆盖从起始行到结束行的完整文本块。

字段：

| 字段 | 类型 | 含义 |
|---|---|---|
| `startRowIndex` | 整数 | 起始行，从 1 开始 |
| `endRowIndex` | 整数 | 结束行，从 1 开始，包含该行 |

示例：

```json
{
  "kind": "multiLine",
  "startRowIndex": 10,
  "endRowIndex": 14
}
```

解析规则：

- 起始行和结束行必须存在。
- 结束行不能早于起始行。
- 范围从起始行行首到结束行行尾，不包含结束行之后的换行符。

写入与重定位：

- 输入值直接替换完整多行范围。
- 编辑器跨行编辑时同时映射起始行和结束行。

## 9. 不定行 `marker`

适用场景：目标行号会变化，但内容前后存在稳定的文本标记。

字段：

| 字段 | 类型 | 含义 |
|---|---|---|
| `startMarker` | 字符串 | 起始标记，非空 |
| `endMarker` | 字符串 | 结束标记，非空 |
| `occurrence` | 整数 | 起始标记出现序号，从 0 开始 |

解析规则：

- 找到第 `occurrence + 1` 个起始标记。
- 从起始标记之后查找第一个结束标记。
- 返回两个标记之间的文本，并裁剪首尾空白。
- 找不到起始标记或结束标记时定位失败。
- 当前实现不支持嵌套标记、正则标记或转义标记。

示例：

```json
{
  "kind": "marker",
  "startMarker": "RESULT_BEGIN",
  "endMarker": "RESULT_END",
  "occurrence": 0
}
```

写入与重定位：

- 输入值直接替换两个标记之间的有效文本范围。
- 标记文本本身不会被修改。
- 编辑器修改后不调整规则字段，而是在新文本上重新解析。

## 10. JSON 路径 `jsonPath`

适用场景：目标位于 JSON 对象属性或数组元素中。

字段：

| 字段 | 类型 | 含义 |
|---|---|---|
| `path` | 字符串 | JSON 路径，默认 `$` |

支持的路径形式：

- 根路径：`$`
- 点号属性：`$.results.maximum`
- 数组索引：`$.results[0]`
- 方括号字符串键：`$["result-key"]`
- 单引号字符串键：`$['result-key']`

当前不支持通配符、过滤表达式、递归下降和完整 JSONPath 函数。

解析规则：

- 空路径或无效路径定位失败。
- 数字段要求当前值位于数组中。
- 字符串段要求当前值位于对象中。
- 数组索引越界或对象键不存在时定位失败。
- 字符串值提取后去掉 JSON 引号；对象、数组、数字、布尔和 `null` 返回其 JSON 文本。

示例：

```json
{
  "kind": "jsonPath",
  "path": "$.results[0].maximum"
}
```

写入与重定位：

- 原值是 JSON 字符串时，输入值按合法 JSON 字符串编码。
- 原值是数字、布尔或 `null` 时，写入去除首尾空白后的输入值。
- 原值是对象或数组时，输入值必须是合法 JSON，并重新编码后写入。
- 写入不会改变路径字段。
- 编辑器修改后不调整规则字段，而是在新文本上重新解析。

## 11. XML 路径 `xmlPath`

适用场景：目标位于 XML 元素文本或属性值中。

字段：

| 字段 | 类型 | 含义 |
|---|---|---|
| `path` | 字符串 | XML 元素、属性或文本路径，默认空字符串 |

支持的路径形式：

- 元素文本：`/root/item/text()`
- 元素属性：`/root/item/@maximum`
- 重复元素序号：`/root/item[2]/@maximum`
- 省略元素序号时默认使用 `[1]`

解析规则：

- 路径按 `/` 分段，支持元素名、可选的正整数序号、末尾 `@属性名` 或 `text()`。
- 路径必须从根元素开始，不能直接写某个深层元素名。
- 元素不存在、属性不存在、元素没有文本内容或 XML 标签不完整时定位失败。
- XML 注释、CDATA 和声明会被跳过。
- 属性值会解码常见 XML 实体；元素文本会裁剪首尾空白。
- 当前实现不是完整 XPath，不支持通配符、谓词表达式、轴、递归查询和命名空间解析。

示例：

```json
{
  "kind": "xmlPath",
  "path": "/results/stress[1]/@maximum"
}
```

写入与重定位：

- 写入前会转义 `&`、`<`、`>`、`"` 和 `'`。
- 属性和元素文本都按同一规则写回。
- 写入不会改变路径字段。
- 编辑器修改后不调整规则字段，而是在新文本上重新解析。

## 12. 模式匹配 `pattern`

适用场景：目标可由稳定的正则表达式识别，但行号会变化。

字段：

| 字段 | 类型 | 含义 |
|---|---|---|
| `pattern` | 字符串 | 正则表达式，默认空字符串 |
| `flags` | 字符串 | 用户标志，默认空字符串 |
| `captureGroup` | 整数 | 捕获组序号，从 0 开始，默认 `0` |
| `occurrence` | 整数 | 匹配出现序号，从 0 开始，默认 `0` |

解析规则：

- 正则表达式不能为空。
- 用户标志会过滤为 `g`、`i`、`m`、`s`、`u`、`y`、`d`，并自动补充 `g` 和 `d`。
- 找到第 `occurrence + 1` 个匹配。
- `captureGroup` 选择要返回的匹配组；`0` 表示整个匹配。
- 正则语法无效、没有匹配、捕获组不存在或捕获文本为空时定位失败。
- 返回值不自动裁剪首尾空白。

示例：

```json
{
  "kind": "pattern",
  "pattern": "maximum\\s*=\\s*([0-9.]+)",
  "flags": "i",
  "captureGroup": 1,
  "occurrence": 0
}
```

写入与重定位：

- 输入值直接替换捕获组对应的字符范围。
- 不自动做 JSON、XML 或语言字符串转义。
- 写入不会改变正则、捕获组或出现序号。
- 编辑器修改后不调整规则字段，而是在新文本上重新解析。

## 13. 写回与重定位总表

| `kind` | 输入写回格式 | 编辑器跨行重定位 |
|---|---|---|
| `autoPosition` | 原文 | 映射起始行和结束行 |
| `rowColumn` | 原文 | 映射起始行和结束行 |
| `delimited` | 原文 | 映射 `rowIndex` |
| `startColumn` | 原文 | 映射 `rowIndex` |
| `wholeLine` | 原文 | 映射 `rowIndex` |
| `multiLine` | 原文 | 映射起始行和结束行 |
| `marker` | 原文 | 规则不变，重新解析 |
| `jsonPath` | JSON 类型感知编码 | 规则不变，重新解析 |
| `xmlPath` | XML 实体转义 | 规则不变，重新解析 |
| `pattern` | 原文 | 规则不变，重新解析 |

## 14. 扩展新策略

新增定位策略时应同步完成：

1. 在 `src/lib/locators/model.ts` 增加定位器类型并扩展 `LaunchLocator`。
2. 在 `src/lib/locators/strategies/` 新增策略模块，实现创建、解析、编辑器状态、重定位、写回、摘要和详情。
3. 在 `src/lib/locators/registry.ts` 注册 `kind` 和界面模式。注册表类型会检查是否遗漏。
4. 在 `src/components/program/locator-editor/` 增加字段编辑器并注册到 `LOCATOR_FIELD_EDITORS`。
5. 增加解析、写回、重定位、工程往返和架构注册表测试。
6. 更新本文档。
