# 变量定位规则与扩展指南

变量定位器使用统一文本解析规则，不再根据 `.ccl`、`.cse`、`.py`、`.wbjn` 或其他扩展名选择不同解析器。文件扩展名只用于编辑器语法高亮，不改变变量识别、写入范围或输出提取行为。

## 统一解析流程

`parseVariables(source)` 接收纯文本并执行以下步骤：

1. 按行扫描文本，计算绝对字符范围。
2. 跳过三引号字符串内部的行，避免把字符串中的示例文本当成真实赋值。
3. 查找不在比较表达式、类型标注或容器内部的 `=`。
4. 解析左侧变量名，支持普通名称、点号属性名和索引表达式。
5. 解析右侧字符串、数值、表达式和尾部 `[单位]`。
6. 收集缩进块路径、控制流路径和可关联的上游变量值。
7. 生成统一的 `ParsedVariable` 数据。

变量解析不接收文件路径、扩展名或 `SourceFlavor` 参数。相同语法无论放在什么扩展名的文件中，都得到相同结果。

## ParsedVariable

统一解析结果包含：

| 字段 | 含义 |
|---|---|
| `variableName` | 变量或属性名 |
| `value` / `rawValue` | 可编辑值和完整原文 |
| `unit` | 尾部单位文本 |
| `line` | 从 1 开始的行号 |
| `nameRange` | 变量名绝对字符范围 |
| `valueRange` | 可替换值的绝对字符范围 |
| `unitRange` | 单位绝对字符范围 |
| `path` | 缩进块、控制流和上游上下文路径 |
| `contextValues` | 关联到的上游变量值 |

## 定位模式

程序启动台允许为参数显式选择定位模式：

| 模式 | 用途 |
|---|---|
| 自动 | 记录选区起始行列和结束位置，按坐标定位 |
| 固定长度 | 起止行和起止列组成的精确范围 |
| 分段 | 按分隔符和字段序号取值 |
| 起始列 | 从指定行、指定列到行尾 |
| 整行 | 指定行的完整文本 |
| 多行 | 起止行组成的完整范围 |
| 不定行 | 两个稳定标记之间的内容 |
| JSON 路径 | `$.results[0].maximum` 等路径 |
| XML 路径 | `/root/item[1]/@attribute`、`/root/item/text()` |
| 模式匹配 | 正则表达式、捕获组和出现序号 |

完整字段、默认值、示例、解析规则和限制见 [定位策略规格](./locator-strategies.md)。

定位器类型和策略接口位于 [model.ts](../src/lib/locators/model.ts)，模式与策略映射位于 [registry.ts](../src/lib/locators/registry.ts)，具体实现位于 [strategies](../src/lib/locators/strategies)。定位字段编辑器位于 [locator-editor](../src/components/program/locator-editor)。

## 写回原则

- 自动和固定长度绑定只替换选区的坐标范围，不使用变量名或相邻文本匹配。
- 分段、起始列、整行、多行、不定行和模式匹配按原文写回，不自动增加语言字符串引号。
- JSON 字符串写回会编码为合法 JSON 字符串；数字和布尔值按原始 JSON 类型写入。
- XML 属性和文本写回会转义 XML 实体。
- 多输入写回先校验全部范围，再从文本末尾向前替换，避免偏移变化。
- 定位失败或出现歧义时返回错误，不猜测目标位置。

## 扩展规则

新增通用赋值语法时，应修改统一解析器的语法层，而不是增加文件类型分支。新增定位方式时，应同步修改 `LaunchLocator` 类型、新增独立策略模块、注册模式映射、增加字段编辑器和对应的解析/写回/重定位测试。具体步骤见 [定位策略规格](./locator-strategies.md#14-扩展新策略)。

以下内容仍属于文本启发式边界：

- 不验证程序运行时类型和作用域。
- 不执行表达式。
- 不构建完整 Python、JSON 或 XML AST。
- 三引号字符串内部默认不参与变量解析。
- XML 支持常见的元素、属性和文本路径，不覆盖完整 XPath。
