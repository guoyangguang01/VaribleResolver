# 程序启动与参数绑定

程序启动台运行在 Electron 桌面客户端中，用于把一个本机程序的输入文件、参考输出文件和参数定义组织在一起。手动保存工程时会更新已修改的来源文件，同时把绑定文件复制到工程目录；运行程序时从工程定义创建独立工作区，不修改工程定义或来源文件。

## 使用流程

1. 在左侧“资源”视图中通过系统文件选择器导入一个或多个本机文本文件。
2. 从文件列表选择文件，在中间编辑器中选中变量、值或任意文本片段。
3. 在选区上点击鼠标右键，选择“添加为输入参数”或“添加为输出参数”创建绑定。
4. 设置参数名、类型、默认值、单位和备注。输入参数的当前值可直接修改，并可恢复为默认值；输出参数只保存定位规则和参数元数据。
5. 填写程序路径、参数和工作目录。
6. 编辑后点击“保存”或按 `Ctrl+S`，客户端会保存工程并更新已修改的来源文件。
7. 点击“运行程序”，客户端先保存工程定义，再创建 `runs/<runId>` 独立工作区。
8. 客户端在运行工作区中按定位规则写入输入，按启动配置启动程序。
9. 程序结束后从运行工作区发现实际输出文件，再按输出定位规则提取参数。

## 定位规则

变量解析不再根据 `.ccl`、`.py`、`.wbjn` 等文件扩展名切换规则。所有文本使用同一套赋值识别逻辑；扩展名只用于编辑器的语法高亮和初始语言提示。

创建绑定时可以选择独立识别模式：

- **自动**：记录当前选区的起始行、起始列和结束位置，直接按坐标定位，不判断变量名或相邻文本。
- **固定长度**：使用起止行、起止列确定精确范围。
- **分段**：按指定分隔符和从 `0` 开始的分段序号定位。
- **起始列**：从指定行的起始列定位到行尾。
- **整行**：以指定行作为完整参数。
- **多行**：使用起止行覆盖完整的多行范围。
- **不定行**：使用起始标记和结束标记定位，适合行号会变化的输出。
- **JSON 路径**：支持 `$.results[0].maximum`、`$["key"]` 等路径。
- **XML 路径**：支持 `/root/item[1]/@attribute` 和 `/root/item/text()`。
- **模式匹配**：使用正则表达式、标志、捕获组和出现序号定位。

自动和固定长度模式按原始坐标直接写回，不根据 Python 引号或变量语法自动转义。输入内容必须与选区范围及目标文件语法保持一致。

左侧栏可在“资源”和“参数”视图之间切换。参数视图按“文件 → 输入/输出 → 参数名”组织树形结构，适用于上百个参数同时浏览，并支持方向筛选和按参数名、类型、默认值、备注、文件路径或定位模式搜索。参数树只显示名称和数量，详细字段在右侧“参数属性”标签中编辑。

参数类型包括文本、数值、布尔和路径。运行程序前会按以下规则校验当前输入值：

- 文本：不限制取值内容。
- 数值：必须使用有效数字或科学计数法。
- 布尔：接受 `true` 或 `false`。
- 路径：不能为空。

参数类型不包含额外范围、枚举或路径模式字段。新参数会根据选中的内容自动推断数值或布尔类型，其余默认使用文本类型。

参数类型不改变写回策略。所有输入仍只替换定位规则确定的字符范围，不添加 JSON 引号、XML 转义或语言字符串字面量。

参数属性中的“修改定位”会切换到右侧“定位规则”标签。此时可以在编辑器中拖选新内容，选区会自动切换为自动模式并更新起始/结束行列；随后点击“应用定位”保存，或点击“取消”放弃修改。底部“运行输出”面板默认折叠，仅显示运行命令、标准输出、标准错误和执行状态。

在编辑器中插入或删除行时，自动定位、固定长度、起始列、整行、多行和分段定位的行号会跟随移动。直接改写目标文本会更新参数默认值，但不会修改执行模式中的当前输入值。目标内容被完整删除或剪切后，参数显示“定位失效”；撤销删除会在原位置恢复原默认值时自动恢复定位。第一阶段不处理同一行内目标文本前方的列偏移。

## 命令参数

参数输入遵循常见的命令行引号规则，例如：

```text
--input "case one.ccl" --material @case[In].material_name
```

启动参数只使用 `@文件名[In].参数名` 引用输入值。程序路径和含空格的参数会在生成的命令中加引号。

启动参数也支持 `@文件名[In].参数名`，例如：

```text
--input input.ccl --material=@case[In].材料 --pressure=@CFX1[In].入口压力
```

## 输入参数引用

当同一个逻辑输入出现在多个文件中时，可以创建一个主输入参数，并让其他输入参数通过“引用主参数”字段指向它：

```text
主参数：入口温度 = 550
别名：  入口温度副本 = @CFX1[In].入口温度
```

规则如下：

- 输入赋值只处理主参数，运行时会自动把主参数值写入所有引用文件。
- 输入引用格式为 `@文件名[In].参数名`，例如 `@CFX1[In].入口温度`。
- 文件名可以带扩展名，也可以省略；解析时按最后一个点拆分文件名和参数名。
- 文件名和参数名组合必须唯一，否则执行前会报告歧义。
- 引用参数不直接接受输入赋值；若 CLI 指定引用参数，会提示改为覆盖主参数。
- 引用链会解析到最终主参数；循环引用、目标不存在和类型不一致都会在执行前报错。
- 有文件绑定的输出参数不支持参数引用。

## 自由参数

参数面板中的“添加自由参数”按钮提供“自由输入”和“自由输出”两个选项，用于创建不关联任何文件的参数。自由参数没有文件路径和定位规则。

```text
参数主键：自由参数.材料
当前值：  steel
```

启动参数可以这样引用：

```text
--material @自由参数[In].材料
```

自由输入参数规则：

- 参数主键使用保留作用域 `自由参数`。
- 不参与文件写回，也不会修改任何输入文件。
- CLI 可以使用 `--set "自由参数.材料=aluminum"` 覆盖。
- 文件参数可以通过 `@自由参数[In].参数名` 引用自由参数的值。

自由输出参数规则：

- 不执行文件提取。
- 可以配置 `@文件名[Out].参数名` 引用一个已绑定的输出参数。
- 引用值优先；引用不可用时，可以使用手动填写的值作为兜底。
- 没有引用时直接返回手动填写的输出值。
- 引用和手动值都可以留空，此时输出值为空。

## 工程目录

点击“保存工程”后选择一个父目录，客户端会创建一个包含完整配置和引用文件的工程目录：

```text
ProjectName/
  project.json
  launch.json
  parameters.json
  outputs.json
  files/
    input.ccl
    result.txt
  runs/
    run-20261109-093000-001/
      ...本次运行使用的工程副本和输出
```

- `project.json` 保存工程元数据、版本、文件相对路径清单和原文件路径。
- `launch.json` 保存启动方式、程序路径、启动参数、工作目录和环境变量。
- `parameters.json` 保存输入输出参数、类型、默认值、单位、备注、当前值和定位器。
- `outputs.json` 保存参考输出、运行路径、必需性和是否复制参考文件。
- `files/` 保存工程引用文件的完整内容。
- `runs/` 保存本机运行工作区，不参与工程分发。

点击“打开工程”并选择工程目录，即可恢复全部文件、参数和程序启动配置继续修改。工程不会封装为单个 JSON 文件。

“新建工程”或 `Ctrl+N` 会清空当前工作区并回到未命名工程。若当前工程包含未保存的更改，客户端会先确认是否放弃这些更改。

“保存”和“另存为”行为不同：

- “保存”或 `Ctrl+S` 会更新工程目录，并把已修改的内容回写到导入时的原文件。
- “另存为”或 `Ctrl+Shift+S` 只创建新的工程目录，不修改原文件。
- 运行程序前的内部保存只更新工程定义；执行工具在独立运行工作区中操作，不修改工程定义或原文件。

工程目录只使用当前 `schemaVersion: 4`。参考输出默认不进入运行工作区。

## 数据与限制

- 文件和绑定状态保存在当前客户端会话中。
- 工程定义以文件相对路径组织绑定文件；执行工具只写回当前运行工作区。
- 启动方式支持直接启动和 Shell 命令；工作目录可以是运行工作区内的相对路径，也可以显式配置本机绝对路径。
- 工作目录会作为子进程的工作目录传递给本机程序。
- 标准输出和标准错误各限制为 1 MB，程序执行不设置超时。
- 导入文件最大为 8 MB，不限制扩展名，但必须是可识别的文本内容。

## 默认 fa1 测试工程

客户端启动时自动打开 `default-project`。这是一个完整的 schemaVersion 4 工程目录，包含：

- `project.json`、`launch.json`、`parameters.json` 和 `outputs.json`。
- `files/` 下的 7 个独立工程文件。
- 从 `fa1.config` 转换得到的 152 个参数，其中 138 个输入、14 个输出。

开发环境直接读取仓库中的 `default-project`，安装后读取应用资源目录中的 `default-project`。默认工程文件和路径均指向自身 `files/` 目录，不读取 `testData`。修改默认工程后点击“保存”会转为“另存为”，避免写回内置工程。

`testData` 仅用于开发和测试，以及通过 `npm run default:create` 重新生成默认工程，不包含在安装包中。
